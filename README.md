# genco-fdia

Stealthy false-data injection (FDI) against a grid foundation model used as a physics oracle.
Entry for the GridFM GENCO Challenge. The write-up is in [`submission/writeup.md`](submission/writeup.md).

**What it does.** An attacker rewrites the telemetry of 8 substations with a physics-consistent lie
whose realism depends on how much of the grid model it knows (`k`). A physics check solves power
flow from the reported injections and compares the implied voltages and line flows with the
reported ones. The oracle is AC Newton-Raphson (reference), DC, or GENCO (`gridfm-graphkit`).
An independent PMU line-flow check and a fused score are reported alongside.

**Main findings** (IEEE 118; numbers are regenerated by `scripts/headline_numbers.py`)
- With an exact oracle the physics check catches the attack until the attacker's model is nearly
  perfect; DC is not a usable oracle; PMU cross-checking is independent of `k`.
- GENCO's error floor relative to sensor noise sets the detection threshold: the released
  checkpoint's clean threshold is 7x (datakit scenarios) to 19x (case-file operating points)
  that of Newton-Raphson.
- A short fine-tune specialises: it lowers the threshold in its training regime and raises it
  outside it. See the write-up for the numbers and for what is *not* claimed (detection above the
  exact oracle's at full attacker knowledge is surrogate error, not physical detection).

## Reproduce

**CPU only (Newton-Raphson and DC oracles, detectors, figures; about 1 minute)**
```
pip install -r requirements.txt
python scripts/run_experiment.py --n_traj 60 --T 10 --attack_at 5 --seed 1
python scripts/run_experiment.py --n_traj 60 --T 12 --attack_at 5 --ramp 5 --seed 1
python scripts/make_figures.py results/results_nr_ramp1.json results/results_nr_ramp5.json
```

**GENCO oracle (GPU).** Install `gridfm-graphkit` from the `genco-paper-repro` branch and
`gridfm-datakit`, with a torch build matching your CUDA driver, and download the checkpoint:
```
hf download gridfm/genco-pf-datakit --include "case118_ieee/base/seed0/*" --local-dir ckpt
export GENCO_CKPT_DIR=$PWD/ckpt/case118_ieee/base/seed0
python scripts/test_genco_oracle.py                                    # accuracy vs Newton-Raphson, runtime
python scripts/run_experiment.py --oracle genco --n_traj 60 --T 10 --attack_at 5 --seed 1
```

**datakit scenarios, fine-tuning, tables**
```
python scripts/make_datakit_scenarios.py --n_scen 720  --seed 0 --out data/scenarios_118.npz     # test scenarios
python scripts/make_datakit_scenarios.py --n_scen 1500 --seed 1 --out data/scenarios_train.npz   # fine-tuning data (disjoint)
python scripts/run_experiment.py --oracle genco --scenarios data/scenarios_118.npz --n_traj 60 --T 10 --attack_at 5 --seed 1
python scripts/finetune_genco.py --datakit_train data/scenarios_train.npz --minutes 30 --out_dir ckpt_ft
python scripts/headline_numbers.py --check          # verifies every number in the write-up against results/*.json
```
Datakit needs Julia/PowerModels (`gridfm_datakit setup_pm` once) and more memory than a typical
shared login node allows.

**Fine-tuned checkpoints** used in the write-up: https://huggingface.co/hasethi/genco-fdia-finetuned (`mixed/` and `case_file_only/`, same file layout as the base checkpoint; point `GENCO_CKPT_DIR` at one of them, or pass `--genco_ckpt <folder> --tag _ft` to `run_experiment.py`).

On 25 October 2026 a fresh clone of this repository, a new virtual environment from `requirements.txt`
and the CPU commands above regenerated `results_nr_ramp1.json`, `results_nr_ramp5.json`,
`results_nr_ramp1_datakit.json` and `results_nr_ramp5_datakit.json` identical to the committed files

`results_genco_ft_mix_ramp1_datakit.json` on one GB200: every detection rate identical to three decimals,
clean thresholds within 2e-5 relative (GPU last-bit differences; the script allows 0.02 / 2%).

## Layout
- `src/grid.py`: IEEE 118 parser, Ybus, AC Newton-Raphson, DC power flow.
- `src/attacks.py`: load trajectories, the `k`-parameterised stealthy attacker, measurement noise.
- `src/detect.py`: physics residual, temporal jump, PMU line cross-check, fusion, calibration.
- `src/genco_oracle.py`: the GENCO adapter (graph built from our grid, pushed through graphkit's own pipeline).
- `scripts/`: experiment runner, figures, adapter acceptance test and parity test, datakit scenario generation,
  fine-tuning, and example Slurm helpers (`slurm_gpu.sh`, `slurm_cpu.sh`, `setup_env.sh`, `run_ft.sh`, `run_all_genco.sh`); they need your own work directory (`W`) and Slurm account (`ACCOUNT`) and were written for the cluster we used, so adapt them to your site.
- `results/`: results JSON for every run in the write-up, and the figures.

## Notes on what is and is not verified
- The adapter feeds the model the same input tensors as graphkit's own pipeline (checked to 3e-7) and the released checkpoint reproduces datakit's solved state to about 0.1 degrees on a datakit scenario.
- Net injection is split into load and generation by a stated rule (see write-up, Method 4); that is an adapter choice.
- Each fine-tune is a single training seed; no seed-to-seed variance is reported.
- Steady-state, transmission-only, synthetic sensor noise, PMU channel assumed uncompromised, no network-layer evidence.
